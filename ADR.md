## Розгляд альтернатив

### **1. Веб-фреймворк**
- **FastAPI** — асинхронність, автоматична документація Swagger, швидкий старт, гарна інтеграція з SQLAlchemy.   
- **Django** — надлишковий для мікросервісу.

**Обрано:** *FastAPI*  
**Причина:** мінімалістичний, асинхронний і сучасний фреймворк із вбудованою підтримкою OpenAPI-документації та легким підключенням залежностей.

---

### **2. База даних**
- **PostgreSQL** — потужна реляційна БД, JSON-поля для гібридних даних, підтримка індексів.  
- **MongoDB** — гнучка JSON-структура, складніша аналітика.  
- **SQLite** — легка, але не підходить для продакшен-навантаження.

**Обрано:** *PostgreSQL*  
**Причина:** ACID, SQL-запити для аналітики, JSON поля.

---

### **3. Черга повідомлень**
- **Redis** — простий у налаштуванні.
- **NATS** — легкий брокер, низька затримка, інтеграція з Python.

**Обрано:** *NATS*  
**Причина:** підходить для мікросервісного сценарію — швидкий і асинхронний .

---

### **4. ORM**
- **SQLAlchemy** — стабільна ORM з підтримкою асинхронності.  

**Причина:** добре документована, анотована, з підтримкою asyncio й Alembic для міграцій.

---

### **5. Тести**
- **Pytest** — стандарт, асинхронна підтримка.  

**Причина:** дозволяє просто писати unit та integration-тести.

---

## Рішення
Архітектура:  
FastAPI (API) → NATS (черга) → worker (обробка подій) → PostgreSQL (збереження).

Використано асинхронний підхід для підвищення продуктивності, простий rate-limiter для стабільності, CLI для імпорту історії та повну контейнеризацію через Docker Compose.
